# Анализ материалов и архитектура

## Назначение

Персональный сайт Расула Ахметова, backend-разработчика из Астаны. Аудитория: работодатели, технические руководители и заказчики. Задача: дать понятное представление об опыте, стеке и способе связаться. Резюме определяет фактическое содержимое. Фото дают визуальный материал; они не используются как доказательство модельной профессии.

## Страницы и сценарии

`/` — знакомство, стек, опыт и переход к контакту; `/experience` — хронология и навыки; `/projects` и `/projects/:slug` — опубликованные кейсы; `/about` — профиль, образование, языки и форматы занятости; `/contact` — валидируемая заявка; `/privacy` — описание обработки данных; `/studio` — закрытый кабинет; `/admin/` — CMS.

Внешних аккаунтов посетителей нет. Закрытый кабинет нужен владельцу для просмотра заявок. Изменение контента и статусов выполняется в Django Admin с отдельной штатной сессией Django. Backend принимает JWT только для API; стандартный Django Admin использует свою CSRF-защищённую session authentication.

## Данные

Один экземпляр SiteSettings содержит профиль и SEO. Experience хранит компании и даты, SkillGroup — категории технологий. Project содержит отдельные опубликованные кейсы. Collection объединяет Photo; неопубликованные элементы не попадают в публичные ответы. ContactRequest хранит сообщения и согласие. RefreshSession обеспечивает ротацию и отзыв. PostgreSQL также хранит общий кеш throttling, чтобы лимиты были согласованы между workers.

## API

Версия `/api/v1/`. Публичное чтение: site, experience, skills, projects, collections. По slug возвращается отдельная подборка или проект. `POST contact/` принимает сообщение с CSRF. `GET inbox/` доступен staff-пользователю, поддерживает пагинацию, status, search, ordering. Auth: csrf, login, refresh, logout, me. Полный контракт — `openapi.yml`.

## Frontend

React Router Framework Mode, Vite и Node SSR; strict TypeScript. Feature auth, shared API/types/UI, страницы и widgets разделены по ответственности. RHF + Zod обеспечивают формы; повторная серверная валидация обязательна. Tailwind и CSS-токены задают общий дизайн. Компонент Button следует shadcn/ui, использует Radix Slot; публичная фотогалерея удалена. Motion применяется к элементам интерфейса с учётом reduced motion. Нет избыточного GSAP для простых переходов.

## Дизайн

Редакционный стиль Serif: Playfair Display, Source Sans 3, IBM Plex Mono, ivory-фон, золотой акцент и тонкие разделители. Первый экран показывает предложение клиенту и профессиональный портрет. Фактические навыки и опыт находятся на главной. Без вымышленных клиентов, процентов улучшения, проектов и отзывов. На мобильном сетки переходят в одну колонку; интерактивные элементы поддерживают клавиатуру и видимый фокус.

## SEO и GEO

SSR обеспечивает содержимое без JavaScript; canonical строится от CMS site_url. Sitemap отражает только опубликованные проекты/подборки. Технические страницы исключены; до запуска включён noindex. Person содержит профессию, город и навыки из резюме; рейтингов, LocalBusiness и необоснованных результатов нет. Географическая информация ограничена реальной Астаной, без искусственных городских страниц.

После запуска: проверить URL в Search Console и Bing Webmaster, sitemap, серверный HTML и структурированные данные. Отдельно проверять видимость брендового запроса и корректность сведений в AI-ответах, фиксируя дату и фактические цитаты. Полевые Web Vitals требуют данных реальных посещений; результаты лабораторной проверки не заменяют p75.

## Инфраструктура

В production Traefik завершает TLS, автоматически выпускает сертификаты Let's Encrypt (HTTP-01) и направляет весь трафик на nginx-шлюз; локально nginx публикуется напрямую на :80. Nginx отдаёт Django static и медиа из read-only volumes, проксирует `/api/` и `/admin/` в Gunicorn, остальное — в SSR. Django работает через Gunicorn WSGI; `collectstatic` выполняется при старте backend в общий volume. PostgreSQL не имеет внешнего порта в production. Секреты только в env. Контейнеры приложений работают без root. Сборки многоэтапные; lock-файлы включены. Docker socket доступен только Traefik в read-only режиме; dashboard не публикуется.

Редизайн и новые модели лендинга: см. serif-redesign.md. SiteSettings хранит hero_title, hero_copy и два портрета; Service хранит направления работы. В sitemap фотогалереи нет.
