# Bootstrap доступа (вручную, после разрешения CEO)

Имя файла сохранено для существующих ссылок; инструкция относится только к доступу.

Код не выдаёт доступ по email. Единственный источник прав — документ
`adminAccess/{uid}` с полями `role` (string) = `admin`, `enabled` (boolean) = `true`.

1. В Firebase Console выберите нужный проект. В Authentication включите Google и Email Link (passwordless), настройте Authorized domains и URL возврата `/admin/login`.
2. Пользователь выполняет вход. В Authentication → Users скопируйте **UID** нужного аккаунта, проверив личность вне приложения.
3. В Firestore Console создайте коллекцию `adminAccess`, ID документа — скопированный UID. Добавьте `role: "admin"`, `enabled: true` именно boolean. Клиент не может создавать, менять или перечислять grants; читает только свой документ.
4. Для отзыва установите `enabled: false` либо удалите документ. Открытая админка отслеживает grant и закрывает контент при отзыве. Email, регистр и провайдер не определяют полномочия.

## Фото сайта

Hero загружает фото только по внешней ссылке из `HERO_PHOTO_URL` в
`src/lib/hero-photo.ts`: https://lh3.google.com/u/0/d/1CqupFBSMr-e2jjZAso4hNFcgJLsssiDB=w1920-h868-iv1?auditContext=forDisplay .
Локальной копии в сборке и резервного фото нет; при ошибке URL не подменяется.
Ссылка должна отдавать изображение без авторизации; доступность внешнего сервиса
не гарантируется сборкой или тестами. Для замены измените константу и выполните
`npm run build`. Публикация требует
отдельного разрешения CEO. CRM не записывает файлы проекта и не загружает фото.
Облачное хранилище для сайта не требуется. Существующие облачные объекты и документ
`siteContent/media` не изменяются и не удаляются; приложение их не использует.

## Настройки аккаунта

Тема сохраняется локально; «Системная» удаляет явный выбор и следует ОС. Google/email-link не требуют пароля Firebase. Кнопка сброса только запрашивает письмо Firebase: пароль меняется по инструкции в письме, а не в интерфейсе. Для установки пароля должен быть включён Email/Password; пароль Google управляется у Google. Ответ Firebase с защитой от enumeration не гарантирует доставку письма.

Ни bootstrap, ни deploy, ни изменение реальных данных в рамках разработки не выполнялись.

## Локальные проверки правил

Firestore и UID-доступ: `npm run test:rules` (локальный эмулятор, без deploy).
